Step 2.1 — Zone 상태 확인

초기 Zone 상태 확인

blkzone report로 모든 Zone의 현재 상태, 시작 LBA, 크기, Write Pointer 위치를 확인합니다.

bash — Zone 목록 조회
# 전체 Zone 목록 (처음 5개)
sudo blkzone report /dev/nullb1 | head -5

# Zone 상태별 개수 집계
sudo blkzone report /dev/nullb1 \
  | grep -oP 'zcond:\s*\d+\s*\(\K\w+' \
  | sort | uniq -c \
  | awk '{printf "  %-8s : %s zones\n", $2, $1}'

# 총 Zone 수 확인
cat /sys/block/nullb1/queue/nr_zones
예상출력 — initial state (all EMPTY)

  start: 0x000020000, len 0x020000, cap 0x020000, wptr 0x000000 reset:0 non-seq:0, zcond: 1(em) [type: 2(SEQ_WRITE_REQUIRED)]

Implicit Open 상태 유발 및 확인 implicit_open.sh

명시적 Open 명령 없이 쓰기를 수행하면 Zone이 자동으로 Implicit Open 상태로 전이됩니다. 초기화부터 상태 확인까지 전체 시퀀스를 한 번에 실행합니다.

implicit_open.sh 동작 순서
  • 전체 Zone Reset — EMPTY 상태 기준선 확인
  • Zone 0에 32MB 순차 쓰기 — OPEN ZONE 명령 없이 fio 직접 실행
  • Zone 0 상태 확인 — WP 이동 및 zcond: oi 전이 확인
  • 전체 Zone 상태 집계 — oi/em 개수 확인
implicit_open.sh 
#!/usr/bin/env bash
# implicit_open.sh — trigger and verify Implicit Open state
# usage: sudo bash implicit_open.sh

set -euo pipefail
DEV=/dev/nullb1

show_zone0() {
    printf 'Zone 0 state: '
    sudo blkzone report "${DEV}" | sed -n '1p' \
      | grep -oP 'wptr\s+\K0x\S+|zcond:\s*\d+\s*\(\K\w+(?=\))' \
      | paste - - \
      | awk '{printf "wptr=%-14s state=%s\n", $1, $2}'
}

printf '── [1] Full reset ───────────────────────────────\n'
sudo blkzone reset "${DEV}"
show_zone0

printf '── [2] Write 32MB (no OPEN ZONE) ───────────────\n'
sudo fio \
  --name=implicit_open \
  --filename="${DEV}" \
  --ioengine=libaio --direct=1 --zonemode=zbd \
  --rw=write --bs=64k --iodepth=1 \
  --offset=0 --size=64m --io_size=32m --numjobs=1 \
  --output-format=normal 2>/dev/null \
  | grep -oP 'write:.*BW=\K\S+' \
  | xargs -I{} printf '  BW: {}\n'
show_zone0

printf '── [3] Zone state summary ───────────────────────\n'
sudo blkzone report "${DEV}" \
  | grep -oP 'zcond:\s*\d+\s*\(\K\w+' \
  | sort | uniq -c \
  | awk '{printf "  %-8s : %s zones\n", $2, $1}'
printf '\ndone\n'
bash — 파일 생성 
vi implicit_open.sh
bash — 파일 권한 부여 및 실행 
chmod +x implicit_open.sh && sudo bash implicit_open.sh
예상출력 — implicit_open.sh

Zone 0 state: wptr=0x000000       state=em
── [2] Write 32MB (no OPEN ZONE) ───────────────
  BW: 1024MiB/s
Zone 0 state: wptr=0x010000       state=oi
── [3] Zone state summary ───────────────────────

참고 Implicit Open은 애플리케이션이 OPEN ZONE 명령 없이 바로 쓰기를 시작할 때 장치가 자동으로 부여하는 상태입니다.
Step 2.2 — 명시적 Zone 제어

Explicit Open → 쓰기 → Close → Finish 통합 실행 zone_lifecycle.sh

Zone을 명시적으로 열고 데이터를 기록하면서 Write Pointer 이동을 관찰한 뒤, Close와 Finish까지 전체 상태 전이 시퀀스를 한 번에 확인합니다.

zone_lifecycle.sh 동작 순서
  • 전체 Zone Reset — EMPTY 상태 기준선 확인
  • Zone 1 Explicit Open — blkzone open → zcond: oe 전이 확인
  • 32MB 순차 쓰기 — Write Pointer 이동 확인 (Zone 절반 기록)
  • Zone 1 Close — blkzone close → WP 유지, zcond: cl 전이
  • Zone 1 Finish — blkzone finish → WP = Zone 끝, zcond: fu 전이
zone_lifecycle.sh 
#!/usr/bin/env bash
# zone_lifecycle.sh — zone state transition (Open -> Write -> Close -> Finish)
# usage: sudo bash zone_lifecycle.sh

set -euo pipefail
DEV=/dev/nullb1

show_zone() {
    printf 'Zone 1 state: '
    sudo blkzone report "${DEV}" | sed -n '2p' \
      | grep -oP 'wptr\s+\K0x\S+|zcond:\s*\d+\s*\(\K\w+(?=\))' \
      | paste - - \
      | awk '{printf "wptr=%-14s state=%s\n", $1, $2}'
}

printf '── [1] Full reset ───────────────────────────────\n'
sudo blkzone reset "${DEV}"
show_zone

printf '── [2] Explicit Open ────────────────────────────\n'
sudo blkzone open --offset 0x20000 --length 0x20000 "${DEV}"
show_zone

printf '── [3] Write 32MB ───────────────────────────────\n'
sudo fio \
  --name=write_z1 \
  --filename="${DEV}" \
  --ioengine=libaio --direct=1 --zonemode=zbd \
  --rw=write --bs=4m --iodepth=1 \
  --offset=64m --size=64m --io_size=32m --numjobs=1 \
  --output-format=normal 2>/dev/null \
  | grep -oP 'write:.*BW=\K\S+' \
  | xargs -I{} printf '  BW: {}\n'
show_zone

printf '── [4] Close Zone ───────────────────────────────\n'
sudo blkzone close --offset 0x20000 --length 0x20000 "${DEV}"
show_zone

printf '── [5] Finish Zone ──────────────────────────────\n'
sudo blkzone finish --offset 0x20000 --length 0x20000 "${DEV}"
show_zone
printf '\ndone\n'

주의 Close 상태에서는 쓰기가 불가능합니다. Finish 상태는 Reset 전까지 영구 봉인됩니다. Close와 Finish의 차이에 주목하세요.
Step 2.3 — Zone Reset (자원 회수)

Zone Reset 통합 실행 zone_reset.sh

단일 Zone Reset과 전체 Zone 일괄 Reset을 순서대로 실행하고, Write Pointer가 Zone 시작으로 복귀하여 EMPTY 상태로 전환됨을 확인합니다.

zone_reset.sh 
#!/usr/bin/env bash
# zone_reset.sh — single zone reset, then bulk reset all zones
# usage: sudo bash zone_reset.sh

set -euo pipefail
DEV=/dev/nullb1

# ── 1) Zone 1 state before reset ─────────────────────
printf '[1/3] Zone 1 state before reset:\n'
sudo blkzone report "${DEV}" | sed -n '2p'

# ── 2) single zone 1 reset ───────────────────────────
printf '\n[2/3] Zone 1 Reset...\n'
sudo blkzone reset --offset 0x20000 --length 0x20000 "${DEV}"
sudo blkzone report "${DEV}" | sed -n '2p'

# ── 3) bulk reset all zones ──────────────────────────
printf '\n[3/3] Bulk reset all zones...\n'
sudo blkzone reset "${DEV}"

sudo blkzone report "${DEV}" \
  | grep -oP 'zcond:\s*\d+\s*\(\K\w+' \
  | sort | uniq -c \
  | awk '{printf "  %-8s : %s zones\n", $2, $1}'

printf '\nFirst 3 zones WP check:\n'
sudo blkzone report "${DEV}" | head -3
printf '\nAll zones restored to EMPTY\n'

참고 Zone Reset은 데이터를 일괄 삭제하고 Write Pointer를 Zone 시작으로 되돌립니다. Conventional SSD의 Trim 명령과 유사하지만 Zone 단위로만 동작합니다.
분석 질문

생각해보기

Q1. Implicit Open과 Explicit Open의 차이점은 무엇이며, 언제 각각을 사용하는 것이 유리할까요?
Implicit Open은 쓰기 요청이 들어오면 장치가 자동으로 zone을 여는 방식이고, Explicit Open은 host가 OPEN ZONE 명령으로 미리 열어 두는 방식입니다. 단순 순차 쓰기에는 Implicit Open이 편하지만, 동시에 열 수 있는 zone 수가 제한된 환경에서는 Explicit Open/Close로 어떤 zone을 열어 둘지 명확히 관리하는 것이 유리합니다.
Q2. Zone Reset이 일반 파일 삭제와 다른 점은 무엇인가요? 낸드 플래시 관점에서 설명하세요.
일반 파일 삭제는 보통 파일시스템 메타데이터에서 해당 공간을 free로 표시할 뿐, 장치의 데이터 영역을 즉시 초기화하지 않습니다. Zone Reset은 zone의 write pointer를 처음으로 되돌리고 zone 전체를 다시 쓸 수 있는 상태로 만드는 장치 수준 동작이며, 실제 NAND 관점에서는 erase block을 재사용 가능하게 만드는 erase/초기화 의미에 가깝습니다.
Q3. Close 상태에서 Write Pointer가 유지되는 이유는 무엇이며, 이것이 Finish와 어떻게 다른가요?
Close는 열린 zone을 닫아 open zone 자원을 반납하지만, 아직 zone에 남은 공간이 있으면 write pointer 위치부터 나중에 다시 이어 쓸 수 있습니다. Finish는 zone을 더 이상 쓸 공간이 없는 것처럼 완료 상태로 만들기 때문에 write pointer가 zone 끝으로 이동하고, 이후에는 reset 전까지 추가 쓰기가 불가능합니다.
